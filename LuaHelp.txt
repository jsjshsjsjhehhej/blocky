TOOL / ZAINO (come Roblox Studio)
================================================================================
Instance.new("Tool") crea un tool nella hotbar (tasti 1-9, clic di nuovo = togli).
Una Part di nome Handle, con Parent = tool, e' l'impugnatura: in mano quando
il tool e' equipaggiato. Le altre Part parentate al tool restano attaccate
al Handle (scostamento rispetto a lui).

  tool.RequiresHandle = true
  tool.CanBeDropped = true
  tool.ManualActivationOnly = false   -- true: il clic non spara Activated
  tool.Enabled = true
  tool.ToolTip = "Spada"
  tool.Equipped / Unequipped / Activated / Deactivated   -- :Connect(function() end)
  tool:Activate()

  local handle = Instance.new("Part")
  handle.Name = "Handle"
  handle.Size = Vector3.new(1, 4, 1)
  handle.Parent = tool
  tool.Parent = game:GetService("Players").LocalPlayer.Backpack

  Humanoid:EquipTool(tool)
  Humanoid:UnequipTools()

Shape sulla Part conta anche in mano e nel mondo: Block, Ball, Cylinder, Wedge.
Un cilindro e' lungo su Size.X (la canna, il manico, la ruota). Un posto
vecchio che allungava il cilindro su Y e lo girava di 90 gradi ora lo vede
doppio: togli quel giro.

Un modello vero, al posto dei pezzi:

  tool.MeshId = "models/revolver.glb"   -- anche .obj o .fbx, path del progetto
  tool.MeshId = ""                       -- torna ai pezzi a codice

Il file sostituisce le Part del tool finche' e' impostato. Grip (scala, ruota,
sposta) resta nel pannello del backpack. Il clic sinistro in gioco spara
Activated, il rilascio Deactivated. Sword e Pistol restano i tool gia' pronti.

Backspace, o Backpack:Drop(), lascia a terra il tool equipaggiato se
CanBeDropped e' true. Le part (il Handle) compaiono davanti al giocatore.
Camminarci sopra lo rimette nello zaino. Senza CanBeDropped il tasto toglie
solo l'oggetto dalla mano.

================================================================================
RETE (quello che crea uno Script)
================================================================================
Uno Script (server) che crea Part, GUI (ScreenGui/TextLabel), Tool o NPC lo
manda a chi e' collegato. Un LocalScript resta su quel telefono.
Le part del place e quelle nuove si riconoscono per id: non si raddoppiano.


Le voci qui sotto sono del motore, non comandi Lua. Non inventare
workspace.StreamingEnabled, ObjectPool o InterestManagement in uno script.

- StreamingEnabled (Studio, Game Settings): in Play le parti lontane non si
  disegnano. Gli slot sono un pool: se finiscono, il resto resta fuori.
- Fisica: un corpo fermo dorme finche' qualcosa non lo urta.
- Instancing: parti con la stessa forma condividono un disegno (anche l'ombra).
- Rete: una part viene mandata solo ai giocatori nel raggio.
- Apri place: la lettura del file avviene in background, il gioco non si blocca.
- Budget di frame: se il frame e' gia' pieno, la fisica non accumula altri passi.

================================================================================
LABEL (3D) vs TextLabel UI
================================================================================
SI  ScreenGui, Frame, TextLabel, TextButton, ScrollingFrame, BillboardGui, SurfaceGui.
    Il Text di un TextLabel / TextButton nasce vuoto: si vede solo quello che lo script scrive.
    BillboardGui o SurfaceGui messi come figli di una Part stanno su quella Part
    e mostrano il Text del TextLabel dentro, non la parola "Label".

PART — proprietà e metodi
================================================================================
part.Name / part.ClassName
part.Position / part.Size / part.Orientation (= Rotation)
  → Vector3 con .X .Y .Z e operatori + - * (scalare) e -unario
  → Size puo' scendere fino a 0.001 stud per lato (modelli dettagliati).
    In Studio i passi sono 1, 0.1, 0.01, 0.001. Shift = passo / 10.
    Snap spento, o Ctrl mentre sposti, = posizione libera.
part.Color / part.BrickColor = Color3.new(r,g,b) | Color3.fromRGB(r,g,b)
part.Material = "Plastic"|"SmoothPlastic"|"Neon"|"Metal"|"Glass"|"Wood"|
                "Concrete"|"Grass"|"Sand"|"Fabric"|"Ice"|"ForceField"
                -- oppure Enum.Material.Wood.  Enum.Material.Wood.Name == "Wood"
                -- typeof(Enum.Material.Wood) == "EnumItem". Vale anche Enum.KeyCode.F.Name
                -- WoodPlanks -> Wood, Sandstone -> Sand, Pebble -> Slate, Cobblestone -> Concrete.
                -- Una volta sola in Output: "Materiale X: il motore usa Y"
part:SetNetworkOwner(nil)      -- non fa niente: la fisica e' gia' del server
local w = Instance.new("WeldConstraint")
w.Part0, w.Part1 = partA, partB   -- le due part restano attaccate. w.Enabled = false le stacca
w.Enabled = true
part.Emissive = 1              -- NUMERO 0..2+ (true viene coercito a 1)
part.PointLight = true
part.LightRange / part.LightBrightness
local luce = Instance.new("PointLight")   -- anche SpotLight, SurfaceLight
luce.Range = 24
luce.Brightness = 2
luce.Color = Color3.new(1, 0.6, 0.2)      -- tinge la luce, non la part
luce.Parent = part                        -- anche dopo la creazione
luce.Enabled = false
part.CanCollide = true|false
part.CanDestroy = true|false   -- Destroy/spada/danni a catena
part.Health / part.MaxHealth   -- Health (MaxHealth aggiornato se serve)
